# OKX 返佣账本

只读核对 OKX Wallet 邀请返佣和手动返还，支持 EVM 与 Solana。按被邀请地址汇总，并在每个网络、合约 / Mint 内精确计算应返、已返、待返和超返。应用不连接钱包、不签名、不转账。

## 开始使用

1. 打开「设置」，填写自己的 EVM / Solana 收款地址，可只填其中一种。
2. 选择实际使用的网络并填写对应 API 凭证，点击「保存设置」。设置窗口中的改动都是草稿；直接关闭不会应用。
3. 点击「开始同步」。首次查询完整历史；以后按钮会按进度显示「同步新增」或「继续未完成」。运行中可暂停，已完成的记录和检查点保留。
4. 在「地址」查看每个地址的资产明细；在「待核对」处理不能自动归属的流水。筛选支持勾选多项、方向、搜索、金额下限与排序，常用条件会保存在此设备。
5. 不确定的记录可打开详情，填写用途、被邀请地址和判断原因后保存。人工判断独立于链上原始记录，可以撤销；可将与返佣无关的付款改为「其他」，避免自动抵扣。

统计金额以当前筛选范围为准。不同网络、不同合约不互相冲抵，也不会因代币同名而合并。链上币数使用整数精度计算，展示缩写不改变原始数值。

默认将差额绝对值**严格小于 0.1 USD** 的资产视为结清，可在设置里更改或关闭。实际差额始终保留；「阈值内，视为结清」和精确归零分别展示。金额筛选不会隐藏缺少可靠报价的地址。

## 归属与核对

### 返佣必须有协议证明和真实到账

- EVM 官方路由路径：同时核实成功交易、可信事件来源、可确认的直接交易发起人和本钱包实际到账。事件名或金额相同不足以证明归属。
- BNB Chain / Base Settlement：用 `CommissionFeePaid` 的完整 orderUID 关联同回执 `Trade.owner`，核对 UID 内的 owner、资产和到账。归属订单持有人，不能把 Settlement 合约或 solver 当作被邀请人。
- Solana OKX SwapV3：解析官方程序账户布局，核实签名用户、输入代币账户 owner、指定 commission account、转账层级、授权方和实际到账。只在协议规定的输入资产持有人与签名 payer 一致时自动归属；owner 缺失或矛盾时待核对。`feePayer`、Helius 标签或资金来源单独出现时均不能证明返佣。
- 智能钱包不被统一排除。能由协议订单 owner 等证据确认时按该 owner 归属；不能确认最终用户时进入待核对。

同交易的其他来款独立保留。匹配只使用正确网络、资产和可证明付款来源的流水，不借用无关到账金额凑出返佣。已匹配底层流水不重复计入。

自动返还只接受本钱包授权的**直接付款**，并匹配已确认被邀请地址、网络和资产。Solana 需要本钱包签名和正确 transfer authority；EVM 需要交易发起钱包以及与实际付款一致的调用。协议内部转出、delegate 付款和用途不明的转出不能直接抵扣。直接转账也可能是其他业务付款，可人工改为「其他」。

详情区分订单持有人、交易发起人、路由、授权方和手续费支付者，避免把其中一个角色笼统显示为最终对方。

### 待核对、垃圾与纠错

未确认归属的流水保留在「待核对」，不会算作零欠款，也不会自动并入已确认账目。资产名单按完整网络与合约 / Mint 识别；名单外记录进入「疑似垃圾」，原始记录仍保留。信任资产与保留单笔微额记录是不同操作；假 USDbC 等已撤销合约不能通过旧备份或人工分类恢复信任。

已核实的 1 lamport SOL 转入，以及 Base 固定价稳定币中低于 0.001 USD、且有精确直接转账凭证的转入，按 dusting 隔离。明确的返佣凭证优先；不能只凭币名或导入文件自带标记过滤。

重核按「网络＋交易」执行，同交易流水只核验一次。新的完整核验结果会替换该交易旧的机器解析，撤销已失效的费用条目；人工决定另存，不会被机器解析覆盖。旧版缺少当前归属证明的已入账记录会回到待核对，也可在高级设置选择「重新核验已入账记录」。

「核验结果」区分已解决、部分解决、仍待核对、请求失败、缺凭证和未处理，支持查看交易、筛选、导出及仅重试失败项。请求成功不代表已经解决归属。刷新页面不会自动重查。

协议参考：[Settlement 已验证源码](https://base.blockscout.com/address/0x25ed72c3f671b626810a6db597dcfd50f215a423?tab=contract)、[OKX Solana SwapV3 账户布局](https://github.com/okxlabs/Web3-DEX-Router-Solana-V1/blob/main/programs/dex-solana/src/instructions/swap_v3.rs)。Settlement 信任只应用于已验证的 BNB Chain / Base 部署，不泛化到其他链。

## 报价

维护名单中的 **USDC、USDT、USD1、USDT0、USDbC、Robinhood 指定 USDG，以及 Arc 原生 USDC 固定按 1 USD 记账**，这是可解释的记账规则，不是实时市场报价。匹配依据完整网络和合约 / Mint，同名假币不会得到固定价格。[Arbitrum USDT0 官方地址](https://usdt0.to/ecosystem/arbitrum)。

其他资产使用参考行情：原生币优先 CoinGecko；无法取得时使用符合流动性要求的 DEX Screener 市场。代币按网络和合约匹配，选择流动性至少 10,000 USD 的最高流动性交易对。浏览器直连失败时同源代理仅补查缺失部分。

报价显示来源和时间，超过 15 分钟不参与小额结清判断。没有可靠报价时标记缺失，不按 0 或 1 USD 猜测。U / USD 表示美元参考价值，不是历史成交价或保证可成交金额。

## 保存、导入与手机使用

### 设置与历史分开保存

- 设置包含钱包、已选网络、结清规则、合约名单和扫描选项。凭证可选「保存在此设备」或「仅本次会话」。保存前先完整校验，关闭草稿不影响当前配置。
- 钱包历史按 EVM / Solana 账户分别存入 IndexedDB；只更换其中一个地址，不会丢失另一账户的历史。兼容旧版钱包组合数据，原数据保留。多个账户的记录、删除和扫描检查点在同一事务提交；多个页面同时写入发生冲突时会提示，不静默覆盖较新数据。
- 「备份与导出」集中提供历史、设置和当前筛选 CSV。CSV 用于分析，不能用于恢复查询进度。
- 历史备份不含 API 凭证。设置备份只有明确勾选「包含 API 凭证」才导出凭证，且必须设置加密口令。清除凭证会同步清理其他标签页的内存和输入框，并停止持有凭证的任务。

一个导入入口自动识别历史、设置和合约名单。历史导入先预览钱包、网络、记录冲突和人工判断；不同钱包需明确确认切换后才写入，原钱包保留。设置与名单先进入草稿，需要保存才生效。文件错误持续显示，可补充口令、重试或取消。

### 本机状态与外部备份的信任不同

同一设备已核验的本机状态可继续使用。外部文件通过严格格式、金额、地址和钱包校验后，自动归属标记仍视为**待验证**：文件里写着「已核实」不能代替链上证据。本机已验证的扫描进度优先保留。外部文件的完成标记和区块边界不能证明历史完整；缺少本机可信进度时需要补查历史范围，完成后继续增量。独立人工决定会保留，但必须先重新核实基础流水的金额和双方地址，才恢复其用途；文件里的人工标签不能代替真实转账证明。

旧备份内混在流水上的 `reviewed` 等字段不被自动当作新人工决定。导入的「自换币」「已覆盖」「直接转账」标记也不能静默隐藏流水。真实重核会从数据源重建记录，再撤销导入待验证状态。

### 加密与压缩

备份可选口令加密和 gzip 压缩。加密使用 PBKDF2-SHA256 派生密钥、AES-256-GCM 验证内容完整性；口令不保存，遗忘后无法恢复。加密保护导出的文件，不能保护已解锁页面免受恶意脚本或失陷设备影响。本机浏览器存储仍未加密。

大文件解析、校验和加解密在 Worker 中进行，有进度和取消入口，并设有文件与解压后大小限制。已保存的历史由 Worker 直接读取导出；普通备份分块序列化。保存失败时仍可导出内存中的完整记录，不依赖再次保存成功。

历史读取异常时进入保护状态，不能用空账本覆盖原数据。可导出原始数据与恢复存档；确认恢复合法备份时，先在同一事务归档原始数据，再写入备份，失败会回滚。旧原始数据仍可从救援导出中取回。

### 手机与后台

HTTPS 下支持 PWA。Android Chrome 可安装；iOS Safari 使用「分享 → 添加到主屏幕」。离线可看本机历史，查询需要联网。新版本就绪后可点击更新；任务运行期间不会强制刷新。其他旧标签仍打开时暂保留其版本缓存，关闭旧标签并刷新后清理。浏览器与安装后的 App 可能使用独立存储，迁移时用备份文件。

页面隐藏时暂停无关渲染和行情刷新，核验任务按检查点保存。浏览器和手机系统仍可能暂停或终止后台页面，不能保证常驻运行；重新打开后可继续未完成的查询。

## 数据源与额度

| 数据源                                                      | 用途                                                 |
| ----------------------------------------------------------- | ---------------------------------------------------- |
| [Blockscout](https://dev.blockscout.com/)                   | 支持网络的交易、内部转账、代币转账和回执             |
| [Helius](https://dashboard.helius.dev/)                     | Solana 历史与 jsonParsed 交易证据                    |
| [NodeReal](https://dashboard.nodereal.io/)                  | BNB Chain 历史和资产转账索引，不调用收费 debug trace |
| [Etherscan](https://etherscan.io/myapikey)                  | Linea 地址历史与内部转账                             |
| [OKX 开发者平台](https://web3.okx.com/onchainos/dev-portal) | X Layer 历史；需要开发者 Key、Secret、Passphrase     |

Linea RPC 经同源服务端只读转发，在两个固定节点之间容错。仅允许交易、回执、区块和指定历史状态查询，不支持签名、广播或任意目标 URL。

查询按供应商控制并发和间隔，限流时有界退避，暂停可中断等待。历史公开交易证据有容量和过期限制，并合并重复请求；重核先用有效缓存重跑解析，命中缓存不占网络限速。统一的核验面板可选择范围与跳过缓存。后台队列按低水位补充任务，同钱包跨标签互斥，数据源请求在标签和 Worker 之间共享节流。

完成后再次同步使用已有边界：BSC、Linea、X Layer 查新增区块；Solana 使用签名边界；EVM 数据源回查近期区块以覆盖延迟入库和重组，并重新核验重叠交易。旧流水在新窗口未出现时暂缓计账，取得权威交易证据后再恢复；接口失败不会直接删除历史。深于重叠范围的索引补录不能由增量模式保证发现。BSC 起始区块默认 0；首次扫描会尝试用计数接口定位首笔活动并跳过空区间，不支持时回退完整分页。只在明确历史起点时缩小范围，扩大范围会补查，已有记录不删除。

「资源诊断」显示本地记录数、存储估算和本次运行的请求、缓存、耗时与错误统计。它不是供应商账户账单，浏览器存储估算也不等于进程内存。

免费额度、链覆盖和历史可用性以供应商控制台及实际响应为准。应用不会购买额度，额度耗尽或数据缺失会显示未完成。公开部署包含请求大小、同源、方法白名单、并发和平台限流，但这些不能保证免费托管月度额度永远不会用尽；部署者仍应在供应商 / Netlify 控制台检查用量和预算。

## 部署到 Netlify

[一键部署到 Netlify](https://app.netlify.com/start/deploy?repository=https://github.com/JimmyLu69/okx-rebate-ledger)，或在 Netlify 导入此仓库。

`netlify.toml` 已配置 Node.js 22、`npm run build:netlify`、静态目录 `public` 和函数目录 `netlify/functions`。不需要在 Netlify 设置私人 API Key；每位使用者在自己的浏览器填写。

必须使用支持 Functions 的部署方式。Blockscout、X Layer、Linea 和行情回退依赖同源接口，仅上传静态目录无法完整运行。服务端固定上游和只读方法，API 响应不进入浏览器离线缓存；服务端只缓存有界的无凭证公开查询结果。静态发布使用明确文件清单，不发布服务端源码或本地资料。

默认部署设置 CSP、禁止外站嵌入和限制不需要的浏览器权限。服务端代码不记录、持久保存凭证，部署者应避免额外启用请求正文日志。其他链请求按配置直连供应商；报价只发送网络与资产标识，不发送用户账本。

## 开发与结构

```sh
npm test
npm run preview
# 可选：独立浏览器回归与合成性能基准
node tests/browser-smoke.mjs
node tests/pwa-smoke.mjs
node tests/storage-browser.mjs

```

打开 `http://127.0.0.1:52567/`；可用 `REBATE_PREVIEW_PORT` 指定端口。应用没有 npm 运行时依赖。

| 路径                                                            | 职责                                               |
| --------------------------------------------------------------- | -------------------------------------------------- |
| `dist/ledger.mjs`、`solana-classification.mjs`                  | 金额、归属证据、到账匹配与自动分类                 |
| `dist/sync-controller.mjs`、`recheck.mjs`                       | 分页、增量同步、交易索引与重核                     |
| `dist/view-model.mjs`、`app.mjs`                                | 可缓存的派生账目、筛选和界面交互                   |
| `dist/storage.mjs`、`profile-storage.mjs`、`persistence.mjs`                           | 增量 IndexedDB 写入、合并保存与冲突检查            |
| `dist/validation.mjs`、`backup-controller.mjs`、`backup-worker.mjs`、`backup-codec.mjs`、`backup-crypto.mjs` | 导入边界、后台备份和加密                           |

| `tests/`                                                        | 归属全流程、迁移、精度、分页、缓存、导入与安全回归 |

资产身份、固定价规则以 `dist/asset-registry.mjs` 为唯一维护源；构建自动生成兼容白名单。分类与汇总按变化交易更新，金额筛选使用精确十进制，精度冲突只隔离相关资产。静态资源升级仍为原子发布，相同内容从旧版缓存复用。

源码、测试和文档不应包含真实账目、默认用户钱包、API 密钥或个人导出。测试使用合成数据；排查公开链上案例时，也不要将用户本地资料提交进仓库。
